The `PhoneNumber` class now strips formatting and an optional leading country code `1`, then validates NANP rules. It raises the required `ValueError` messages for letters, punctuation, wrong length, a non-1 country code, and area or exchange codes that start with 0 or 1. The cleaned 10-digit number is stored as `number`, with `area_code` and a `pretty()` formatter.
