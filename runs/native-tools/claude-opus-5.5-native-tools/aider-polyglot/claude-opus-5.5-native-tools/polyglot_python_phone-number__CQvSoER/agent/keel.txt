`PhoneNumber` in `phone_number.py` is implemented. It strips punctuation and the optional `1`/`+1` country code, stores the 10 digits in `.number`, and raises a `ValueError` with the required message when a number is invalid. No test file came with the exercise, so I only checked it with a handful of inputs, and those all behaved as expected.

- **Valid inputs:** `+1 (613)-995-0253`, `613.995.0253` and `1 613 995 0253` all give `6139950253`.
- **Invalid inputs:** letters, other punctuation, the wrong number of digits, an 11-digit number not starting with 1, and an area code starting with 1 or exchange code starting with 0 each raised the right message.
- **Extras I added:** `area_code`, `exchange_code` and `subscriber_number` attributes, plus a `pretty()` method that returns `(613)-995-0253`. The instructions didn't ask for these; I included them because the usual tests for this exercise tend to use them.
- **More than one problem:** the checks run in a fixed order (letters, punctuation, length, country code, area code, exchange code), and only the first problem found is reported.
